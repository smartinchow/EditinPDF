# EditinPDF — iOS app on the PdfCraft engine: design

Date: 2026-10-15. Status: approved in conversation (sections 1–2 explicitly; sections 3–6 decided by Claude at the user's request to proceed without further questions).

## 1. Intent

- **What:** EditinPDF, a free, native iOS app (iPhone + iPad) for viewing, organizing and annotating PDFs, built on the open-source PdfCraft engine (pure Rust, MIT OR Apache-2.0, https://github.com/storytold/pdfcraft).
- **Why:** a useful product for the public. Quality, polish and App Store ratings matter more than breadth. Android comes later from the same Rust core.
- **Success for v1.0:** a person can open any PDF from Files/Mail/Share, read it smoothly (pinch-zoom, search, select and copy text, open password-protected files), fix it (rotate, delete, reorder, merge, extract pages) and mark it up (highlight, underline, strikeout, sticky note, ink, text box, shapes) and fill forms — fully offline, with no account and no data collection — and the file saves back where it came from without damaging it.
- **Non-goals for v1.0:** OCR, digital signatures, JavaScript forms, redaction, Office import/export, printing, content editing of existing text, cloud sync, Android (v1.x).

## 2. Constraints and decisions

| Decision | Choice | Why |
|---|---|---|
| Platform order | iOS first; Android later | One UI to polish; Mac + Xcode ready |
| First release scope | Viewer + organize + annotate + forms (milestones M1–M3), shippable after any milestone | User choice "C"; milestones keep release possible at any point |
| App name | EditinPDF | Must not contain "PdfCraft"/"ArtCraft" (brand terms); unrelated "PDFCraft" already in App Store |
| Bundle ID | `app.editinpdf.ios` (set in one xcconfig; change freely) | Placeholder independent of any personal domain |
| Our license | MIT OR Apache-2.0 (same as upstream) | Free app, public repo, maximal reuse; user can change before first public release |
| Upstream pinning | git submodule at a release tag (v0.7.1 to start) | Upstream patches its renderer under `vendor/`; Cargo only honors `[patch]` from a local checkout. Reproducible, offline builds |
| Upstream policy | Never edit the submodule. Needed engine fixes go upstream as PRs; until merged, work around in the bridge | No fork to maintain, no merge conflicts |
| Bridge | Rust crate `editinpdf-core`, UniFFI proc-macros, curated typed API + JSON automation escape hatch | Approach 1 (typed, best UX/perf) chosen over JSON-only and egui-on-iOS |
| UI | SwiftUI app; UIKit where it earns it (tiled page view, page-grid reordering) | Native feel; CATiledLayer matches the engine's tile renderer exactly |
| Document model | SwiftUI `DocumentGroup` + `ReferenceFileDocument` | Files integration, open-in-place, autosave, undo manager for free |
| Min iOS | 17.0, universal (iPhone/iPad) | Mature SwiftUI (`@Observable`), ~95 % device coverage |
| Xcode project | generated by XcodeGen from `ios/project.yml`; generated `.xcodeproj` is committed too | Diff-friendly source of truth, still double-clickable |

## 3. Repository layout and build pipeline

```
EditinPDF/
├── upstream/pdfcraft/        git submodule, pinned to a release tag (never edited)
├── core/                     our Rust workspace
│   ├── Cargo.toml            members: editinpdf-core, uniffi-bindgen
│   │                         [patch.crates-io] hayro, hayro-interpret, hayro-syntax, hayro-jbig2, lopdf
│   │                         → ../upstream/pdfcraft/vendor/*  (mirrors upstream's patch table)
│   ├── editinpdf-core/       bridge crate (lib: staticlib + rlib)
│   ├── uniffi-bindgen/       tiny bin: uniffi::uniffi_bindgen_main()
│   └── scripts/build-xcframework.sh
├── ios/
│   ├── project.yml           XcodeGen spec → EditinPDF.xcodeproj
│   ├── EditinPDF/            app sources, assets, Info.plist keys, PrivacyInfo.xcprivacy
│   ├── EditinPDFCore/        Swift package: generated EditinPDFCore.swift + EditinPDFCoreFFI.xcframework (binary target, built, not committed)
│   └── EditinPDFTests/, EditinPDFUITests/
├── docs/                     this spec, plans, ADRs, THIRD-PARTY-NOTICES.md
├── Makefile                  make setup | core | xcframework | ios | test | update-upstream TAG=…
└── .github/workflows/ci.yml  macOS runner: cargo test, build xcframework, xcodebuild test (simulator)
```

Build pipeline (`core/scripts/build-xcframework.sh`):
1. `cargo build --release -p editinpdf-core --target aarch64-apple-ios` and `--target aarch64-apple-ios-sim` → `libeditinpdf_core.a` each.
2. `cargo run -p uniffi-bindgen -- generate --library <sim .a> --language swift --out-dir …` → `EditinPDFCore.swift`, `EditinPDFCoreFFI.h`, `EditinPDFCoreFFI.modulemap`.
3. `xcodebuild -create-xcframework -library … -headers …` → `EditinPDFCoreFFI.xcframework`.
4. Copy the Swift file and the xcframework into `ios/EditinPDFCore/`.

Xcode never invokes Cargo. `make ios` runs the script then `xcodebuild`. Updating upstream: `make update-upstream TAG=vX.Y.Z` moves the submodule, rebuilds, runs `cargo test`; the bridge is fixed up where upstream's API moved.

Toolchain: rustup stable (upstream `rust-version = 1.95`, edition 2024), targets `aarch64-apple-ios`, `aarch64-apple-ios-sim`; cmake (for `aws-lc-sys`); Xcode 27 (iOS 27 SDK); XcodeGen.

## 4. The bridge: `editinpdf-core`

### 4.1 Shape

- UniFFI proc-macro mode (`uniffi::setup_scaffolding!()`, `#[uniffi::export]`, `#[derive(uniffi::Record/Enum/Error/Object)]`). No UDL.
- One exported object, `PdfDocument` (`Arc<PdfDocument>`), holding `Mutex<Inner>` where `Inner { session: pdfcraft_engine::Session, id: DocId, revision: u64 }`. One engine session per open file.
- `panic = "unwind"` stays (UniFFI converts panics into a Swift error instead of aborting the app). Crate lints: `deny(clippy::unwrap_used, expect_used, panic)` like upstream; `unsafe_code` is not forbidden (UniFFI's generated scaffolding needs it) but our own code has none.
- Every error crossing FFI is a typed enum; messages are human-readable and safe to show.

### 4.2 API (Swift names)

```
func engineVersion() -> String                     // "editinpdf-core 0.1.0 / pdfcraft v0.7.1"

final class PdfDocument {
  init(bytes: Data, password: String?) throws(OpenError)    // NeedsPassword, WrongPassword, Corrupt(msg)
  func pageCount() -> UInt32
  func pageInfo(_ i: UInt32) -> PageInfo            // widthPt, heightPt (view space, rotation applied), label
  func renderTile(page: UInt32, scale: Double, rect: TileRect?) throws(RenderError) -> RenderedTile
        // scale = device px per point; rect in device px at that scale (nil = whole page);
        // RenderedTile { width, height, rgba: Data /* premultiplied RGBA8 */ }
  func pageText(_ i: UInt32) -> PageText            // glyphs: [TextGlyph { text, rect, direction }] in view space
  func search(_ query: String, caseSensitive: Bool) -> [SearchHit]   // { page, rects: [Rect], snippet }
  func pageAnnotations(_ i: UInt32) -> [AnnotationInfo]   // { id, kind, rect, contents, author, modified }
  func formFields() -> [FormField]                  // { name, kind, value, options, page, rect, readOnly }
  func apply(_ edit: Edit) throws(EditError)        // see 4.3
  func undo() throws(EditError) -> String?          // returns label
  func redo() throws(EditError) -> String?
  func canUndo() -> Bool; func canRedo() -> Bool
  func isDirty() -> Bool
  func revision() -> UInt64                         // bumps on every apply/undo/redo; UI invalidates tiles/thumbnails
  func save(mode: SaveMode /* incremental | full */) throws(SaveError) -> Data   // caller writes the file
  func markSaved()
  func extractPages(_ pages: [UInt32]) throws(EditError) -> Data   // new PDF containing those pages ("split")
  func callTool(name: String, argsJson: String) throws(ToolError) -> String   // JSON automation escape hatch (M2+, optional)
}
```

Coordinates: **everything Swift sees is view space** — points, origin top-left, y down, page rotation applied — identical to upstream's text layer and to UIKit. The bridge converts to PDF user space (`PageInfo::view_to_user`) on the way in and back on the way out. Pages are **0-based** in the bridge (Swift convention); the bridge adds 1 where upstream is 1-based.

### 4.3 `Edit` (curated mirror of upstream's `Edit`, ~15 variants)

Pages: `rotatePages(pages, degrees)`, `deletePages(pages)`, `movePages(pages, to)`, `insertBlankPage(at, widthPt, heightPt)`, `insertPagesFrom(bytes, pages?, at)` (merge).
Annotations (`NewAnnotation`): `addTextMarkup(page, kind: highlight|underline|strikeout, quads, color, contents)`, `addNote(page, at, contents, color)`, `addInk(page, strokes: [[Point]], color, width)`, `addTextBox(page, rect, text, fontSize, color)`, `addShape(page, kind: rectangle|oval|line, rect/points, strokeColor, fillColor?, width)`; `deleteAnnotation(page, id)`, `moveAnnotation(page, id, to)`, `setAnnotationContents(page, id, contents)`.
Forms: `setFieldValue(name, value: FieldValue /* text | checked(Bool) | choice([String]) */)`.
Meta: `setInfo(key, value)`. Grouping: `batch(label, edits)` = one undo step.

Adding a variant later is ~20 lines (record + match arm + test).

### 4.4 Rendering and threading

- `renderTile` takes the lock only to snapshot `Arc` bytes of the current display document + revision, then renders outside the lock, so pinch-zoom tiles never wait for an edit and vice versa.
- A small renderer cache keyed by revision (upstream `PageRenderer`). M0 spike decides whether one renderer can be shared across threads; fallback is one renderer per calling thread (thread-local) — the API does not change.
- Tiles are capped at 4096 px per side (upstream limit); the page view asks for ≤ 1024 px tiles.

### 4.5 Tests

`cargo test` in `core/`: fixtures built in-memory with upstream's `pdfcraft-create` (or hand-written minimal PDFs) — a 3-page text document, an encrypted one, one with a form, one with annotations. Every public call has at least one test; edits are checked by re-opening the saved bytes. This suite is the gate for every upstream bump.

## 5. iOS app

### 5.1 Structure (SwiftUI + UIKit)

```
EditinPDFApp            DocumentGroup(newDocument/viewing: PDFFileDocument) { DocumentScreen }
PDFFileDocument         ReferenceFileDocument; owns PdfDocument; snapshot = engine save bytes
DocumentModel           @Observable view-model: current page, zoom, selection, search state, tool mode;
                        applies Edits, registers UndoManager actions, bumps revision → invalidation
DocumentScreen          toolbar, page indicator, sheets (thumbnails/organize, search, comments, licenses)
PageScrollView          UIViewRepresentable → UIScrollView; continuous vertical pages; zoom 0.5–8×;
                        virtualized PageView children (only visible ± 2 pages exist)
PageView                UIView whose layer is a CATiledLayer subclass; draw(in:) → renderTile → CGImage
PageOverlayView         transparent UIView per page: selection, search highlights, annotation hit-targets,
                        in-progress ink/shape drawing; all in view-space points × zoom
ThumbnailStore          NSCache of small renders keyed by (page, revision)
PageGridView            UICollectionView (compositional layout) with drag-reorder, multi-select; actions:
                        rotate, delete, insert blank, insert from file (merge), extract to new PDF (split)
Annotation tools        mode enum: select, highlight, underline, strikeout, note, ink, textBox, rectangle,
                        oval, line; colour + width palette; comment list sheet
Forms                   tap on a field → inline text entry / toggle / picker → setFieldValue → re-render page
LicensesView            renders docs/THIRD-PARTY-NOTICES.md (bundled)
```

### 5.2 Key flows

- **Open:** DocumentGroup hands us a `FileWrapper` → bytes → `PdfDocument(bytes:)`. `NeedsPassword/WrongPassword` → password sheet, retry. `Corrupt` → alert, close.
- **Save:** every applied edit registers an undo action with the environment `UndoManager` (which also calls engine `undo()`); this marks the document dirty so SwiftUI autosaves. `snapshot` → `save(.incremental)` (original bytes preserved; a "Save optimized copy" full save can come later).
- **Render:** `CATiledLayer` calls `draw(in:)` per tile on background threads → `renderTile(page, scale: ctx scale × zoom, rect)` → `CGImage` (premultipliedLast, sRGB) → draw. On `revision` change: affected pages' layers `setNeedsDisplay()`; page reorder/delete/insert rebuilds page frames.
- **Text selection:** long-press → `pageText` → word at point → handles extend by glyph rects → copy. Search: incremental, results list, tap → scroll + highlight.
- **Text markup:** in highlight/underline/strikeout mode, drag over text → glyph rects grouped into line quads → `addTextMarkup`. Note: tap → place → sheet for text. Ink: touch/Pencil points captured in overlay → `addInk`. Text box / shapes: drag a rect → edit → `apply`.
- **Forms:** `formFields()` once per revision; overlay shows tappable fields; `setFieldValue` → engine regenerates appearance → page re-render.
- **Organize:** grid edits are collected and applied as `batch` where natural (e.g., multi-delete) so one undo reverts them.

### 5.3 Errors

Typed bridge errors → Swift alerts with the human-readable message; nothing crashes on a bad file. A failed tile draws blank and logs; a failed edit leaves the document unchanged (engine guarantees) and shows an alert. Rust panics surface as a Swift error (UniFFI), not an abort.

### 5.4 Tests

XCTest unit tests for `DocumentModel` (fixture PDFs in the test bundle): open, page count, edit→revision→undo, save round-trip. One UI smoke test on the simulator: launch, open a bundled sample, scroll, zoom. CI runs both on a macOS GitHub runner after `cargo test` and the xcframework build.

## 6. Milestones

- **M0 — Toolchain and spike (answers, not code to keep):** can every engine crate compile for `aarch64-apple-ios` and `-sim`? Static-lib size? Does `PageRenderer` share across threads? Produces: toolchain installed, `core/` skeleton compiling, numbers written to `docs/adr/0001-ios-build-spike.md`.
- **M1 — Viewer:** bridge open/pages/render/text/search + tests; XCFramework; Xcode project; DocumentGroup app; tiled page view; thumbnails sheet; search; selection/copy; password prompt. TestFlight-able.
- **M2 — Organize:** bridge page edits + `extractPages`; page grid with reorder/rotate/delete/insert/merge/extract; undo/redo; autosave verified against Files.
- **M3 — Annotate + forms:** bridge annotation and form edits; tool modes; comment list; form filling.
- **M4 — Store polish:** app icon, licenses screen + THIRD-PARTY-NOTICES, privacy manifest, document-type registration, CI, README with screenshots, TestFlight.

## 7. Licensing and store compliance

- Ship MIT/Apache license text, upstream `NOTICE`, and the asset credits from upstream `ATTRIBUTION.md` plus our Rust/Swift dependency licenses in an in-app **Licenses** screen (generated into `docs/THIRD-PARTY-NOTICES.md` by `make notices`, using `cargo about` or `cargo deny list`).
- **No ArtCraft marks** anywhere in the app, icon, name, screenshots or store listing (upstream `docs/brand/LICENSE-brand.txt`). The submodule contains them on disk (permitted as a copy of the repository) but nothing under `upstream/pdfcraft/docs/brand` is ever bundled. README may say, in plain text, that EditinPDF is based on PdfCraft by the ArtCraft team.
- OCR models (CC-BY-SA-4.0) are not bundled in v1.0 (OCR not exposed). Fonts: hayro's embedded standard-14 (BSD-3) and upstream's embedded fallback fonts (OFL); optional CJK fallback (`CRAFT_FONTS_DIR`) is a later improvement.
- Privacy: no network, no analytics, no accounts → `PrivacyInfo.xcprivacy` with no collected data; App Store "Data Not Collected".
- No "Adobe"/"Acrobat" in the name or marketing.

## 8. Risks and how they're handled

| Risk | Mitigation |
|---|---|
| An engine dependency doesn't build for iOS (`aws-lc-sys`, `craft-print`, `boa_engine`) | M0 spike finds out first. Fallbacks: cmake for aws-lc; if a crate is hopeless, a minimal upstream PR adding a feature flag, with a temporary `[patch]` of that one crate in our workspace until merged |
| Binary size (JS engine + OCR runtime + renderer) | Measure in M0; release profile `opt-level="s"`, `lto="fat"`, `codegen-units=1`, `strip`; acceptable up to ~40 MB |
| Upstream API churn (alpha, releases every 1–2 days) | Pin to tags; update deliberately; bridge tests catch breakage; small surface to fix |
| Renderer not thread-safe | Thread-local renderer fallback (4.4) |
| Large/hostile PDFs | Engine is fuzzed upstream; UniFFI turns panics into errors; tiles capped; open runs off the main thread |
| Upstream ships its own mobile app | Irrelevant for a free app; our value is the native UX |
